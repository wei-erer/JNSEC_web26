PHP、Python 与 Java

这三种语言在 Web 安全里的分工，其实分得很清楚： Python 是你手里的工具，PHP 是你最常打的靶子，Java 是你迟早要啃的那块硬骨头。 这一讲不追求把三门语言学完，只把各自跟漏洞最相关的那些部分讲透。

第二讲 · 三门语言的基础与安全视角 · 含 1 个 PHP 靶场、1 个脚本实操

这一讲在讲什么

第一讲把网页、URL、HTTP 讲完了，你现在能看懂一个请求在说什么。 但看懂之后呢？你要么得写点东西去打，要么得看懂别人写的代码为什么有洞。 这两件事，分别落在了 Python 和 PHP / Java 上。

三种语言的分工，讲台上那句话说得挺准：

Python 是你的工具，PHP 是你的靶子，Java 是你的远方。

展开说：

  • Python —— 你会用一辈子。跑脚本、批量发包、生成 payload、写爬虫、 跑自动化，都是它。它不强在"能做什么新事情"，而强在同样的事你能少写十倍代码。
  • PHP —— 国内 Web 题的大头。它语法松散、弱类型、历史包袱重， 一个 == 就能翻出一堆绕过。它的坑很集中，学一遍能吃很久。
  • Java —— 大型比赛里真正的难题几乎都在 Java。 反序列化、反射、注解、类加载，这些名字你现在听着像天书， 但它们全都建立在"类、对象、接口"这几个概念上。基础不牢，后面一点都看不懂。

所以这一讲的顺序是：先装环境 → Python 够用就行 → PHP 重点讲弱类型和危险函数 → Java 把 OOP 和反射那套地基打上。能记住多少算多少，剩下的等用到了再回来翻。

PHP 环境：两个法子

PHP 代码得有个解释器才能跑。两种做法：

  1. phpstudy（第一讲装过的话就现成了）。把 .php 文件丢进 www 目录，浏览器访问 127.0.0.1。
  2. WSL 里的 php。命令行一条：
    sudo apt install -y php-cli
    之后用 php -S 127.0.0.1:8082 就能在任意目录起一个 PHP 服务器。 这一讲的靶场就是这么跑的。

Python：写脚本的那只手

你以后写的每一个批量发包、每一个 payload 生成器、每一个把结果整理成表格的小工具， 大概率都是 Python。

和 C 比，它到底省在哪儿

C 语言干任何事之前，先要 #include 一堆头文件，自己管内存，自己写循环遍历。 Python 是"开箱就有一堆现成的轮子"：别人写好的库，一行 import 就能用。

C 里几十上百行的事，在 Python 里可能就是一个函数调用。 这就是它适合写脚本的全部理由 —— 不是能力更强，是同样的活更快干完。

变量、if、循环：看看差别

变量不用声明类型，直接赋值就是定义：

# C 里要写
int c = 1;

# Python 里
c = 1

判断用缩进代替大括号，条件后面跟冒号：

if a > b:
    print("a 大")
else:
    print("b 大")

循环：

for i in range(10):     # 循环十次，i 从 0 到 9
    print(i)

while i > 10:           # 和 C 一样
    i -= 1
缩进就是语法

Python 用缩进划分代码块，不是大括号。混用空格和 Tab 是新手第一大坑， 报 IndentationError 的时候先看这个。

编辑器里把 Tab 设成 4 个空格，养成习惯。

六种数据类型

Python3 有六种标准类型，先记住长什么样，不用背方法：

类型写法干什么用
Number 数字n = 1整数、浮点、复数
String 字符串s = "aaa"文本。Web 里到处都是它
List 列表l = ["a", "b"]有序、可变。最常用
Tuple 元组t = (1, 2)有序、不可变
Set 集合s = set()无序、自动去重
Dictionary 字典d = {}键值对。发请求传参数基本都用它

注意 Python 是动态类型的：同一个名字可以先存数字，后存字符串， 再存列表，它都不拦你。方便，也容易埋 bug —— 跑起来才发现类型不对。

模块、包、库：三个词一个意思

  • 模块（module） —— 一个 .py 文件就是一个模块
  • 包（package） —— 一堆模块放进一个文件夹，就是包
  • 库（library） —— 平时口头说的"库"，可能是模块也可能是包，不用较真

用 import 引进来：

import os                    # 整个模块进来
from os import path          # 只拿里面的一个

requests：三行写个爬虫

先装：

pip install requests

国内装得慢的话，加个镜像源：

pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple

然后，三行：

import requests
res = requests.get("https://www.baidu.com")
print(res.text)

逐行看：

  1. import requests —— 把模块拿进来
  2. requests.get(url) —— 模块里有个 get() 方法， 它模拟浏览器发一个 GET 请求，返回一个装着响应信息的对象
  3. res.text —— 把响应体当文本打印出来

就这样，你已经写了一个爬虫。所谓"爬虫"，就是用程序按规则自动抓取网页内容， 本质和你用浏览器打开页面没区别，只是换成了代码在点。

做题目最常用的四个参数

直接抄作业吧，这四段基本覆盖了八成的题： 

import requests

URL = "http://www.example.com"

# ① GET 参数 —— 拼在 URL 后面
params_ = {"name": "solo", "age": 19}
r = requests.get(URL, params=params_)
# 等价于请求 http://www.example.com?name=solo&age=19

# ② 自定义请求头 —— 改 Host、改 UA 都靠它
headers_ = {"User-Agent": "solo/1.0.0", "Host": "127.0.0.2:7777"}
r = requests.get(URL, headers=headers_)
# 注意：请求头里有 Host 时，requests 会优先用它，而不是 URL 里的主机
#       —— 这正好是第一讲那个 Host 头漏洞的利用方式

# ③ 带 cookie —— 相当于"我已经登录了"
cookies_ = {"token": "access_token"}
r = requests.get(URL, cookies=cookies_)

# ④ 超时 —— 别让脚本卡死在一个请求上
r = requests.get(URL, timeout=2)

POST 也差不多，区别只是参数放哪儿：

data = {"name": "solo", "age": 19}

requests.post(url, data=data)    # 表单格式，Content-Type: application/x-www-form-urlencoded
requests.post(url, json=data)    # JSON 格式，Content-Type: application/json

这两个的区别，就是第一讲里 Content-Type 那一节说的： 后端按格式选解析器，选错了可能绕过某处校验。

挂在 Burp 上跑

写脚本的时候想让 Burp 看到你发的包？加个 proxies 参数： 

proxies = {
    "http":  "http://127.0.0.1:8080",
    "https": "http://127.0.0.1:8080",
}
res = requests.get("http://127.0.0.1:8081/", proxies=proxies)

这样脚本发的请求也会经过 Burp，你能在 HTTP history 里看到它、能改成 Repeater 去改。 调试脚本的时候这个特别有用 —— 脚本发出去的包到底长什么样，看 Burp 最清楚。

os 和 zipfile：CTF 里的日常

Web 题不一定都是 Web，经常要处理压缩包、批量改文件、扫目录。 这些一两个库就够： 

import os, zipfile

# 目录与文件
os.makedirs("./test_dir", exist_ok=True)   # 建目录，已存在不报错
print(os.listdir("./"))                     # 列出当前目录，返回列表
os.remove("a.txt")                          # 删文件
os.rename("1.py", "1_new.py")               # 改名

# 读写文件（with 会自动关文件，别用 open/close 手动管）
with open("a.txt", "w", encoding="utf-8") as f:
    f.write("Hello")

# 压缩包
with zipfile.ZipFile("out.zip", "w") as z:
    for name in os.listdir("./"):
        if name.endswith(".png"):
            z.write(os.path.join("./", name))

with zipfile.ZipFile("out.zip", "r") as z:
    z.extractall("./unzip_dir")

# 带密码的压缩包也支持（爆破时就是这个用法）
with zipfile.ZipFile("protected.zip", "r") as z:
    z.extractall("./out", pwd=b"123456")
为什么这些跟安全有关

因为真实比赛里，你拿到的往往是一个压缩包、一堆文件、一个要跑几百次的脚本。 手工能做的只有验证，批量的事必须交给代码。 这就是 Python 在这里的位置 —— 它不是攻击面，它是你的手。

异步和多线程：为什么爆破快不起来

先说结论：同步写发的请求是一个一个等着回来的。发一个、等服务端回、 再发下一个。一个请求 0.2 秒，跑一万条字典要半小时。

你想的可能是"开多线程"。但脚本跑得多了会发现，纯多线程在这种场景下不一定好： 线程开销大、不好控制并发数、出错难查。

更现代的做法是异步 I/O：一个线程里同时挂着几百个请求， 谁先回来先处理谁，不用为每个请求开一个线程。

Python 里这套东西叫 asyncio，三个概念：

  • 协程（coroutine） —— 用 async def 定义的函数。 它和普通函数的区别是：可以跑到一半停下来，把控制权交出去， 等条件满足了再从停下的地方接着跑。停下的位置就是 await 那一行。
  • 事件循环（event loop） —— 那个"调度员"。它不停地看：谁好了？谁在等？ 好了就推进，在等的就放着。
  • 任务（Task） —— 把协程登记进去，让它从"一张工单"变成"正在推进的活"。 
import asyncio

async def work(n):              # 协程：可以中途让出
    print("开始", n)
    await asyncio.sleep(1)      # 在这里暂停，交还控制权
    print("完成", n)

async def main():
    task = asyncio.create_task(work(1))   # 登记成任务
    await task                            # 等它

asyncio.run(main())             # 事件循环从这里启动
最容易懵的一点

直接调用协程函数 work(1)，它不会执行， 只会返回一个协程对象。必须交给 asyncio.run() 或者 create_task() 才会跑起来。

这和普通函数"调用就执行"的直觉相反，第一次见都会愣一下。

至于真正批量发包，最省事的写法是 aiohttp 或者 asyncio + 线程池。到你真要爆破的时候再深入，现在知道 "同步会慢、异步能快"这件事就够了。

顺带一提：多进程 / 多线程 / 协程怎么选
  • I/O 密集（发请求、读写文件、查数据库）→ 协程或线程池。这是你们绝大多数场景。
  • CPU 密集（算哈希、解密）→ 多进程。Python 有 GIL，多线程在这里没用。
  • 线程池 —— concurrent.futures.ThreadPoolExecutor，标准库自带，写起来比裸线程简单，跑 I/O 任务够用。

用 Python 打一遍第一讲的靶场

把第一讲那个靶场跑起来（python zhulin_lab.py）， 然后新建一个 try.py，把下面这段抄进去跑： 

import requests

base = "http://127.0.0.1:8081"

# 第一关：加个 X-Forwarded-For 头
r = requests.get(base + "/gate/1", headers={"X-Forwarded-For": "127.0.0.1"})
print("第一关:", r.text[:60])

# 第二关：改 Host
r = requests.get(base + "/gate/2", headers={"Host": "admin.internal"})
print("第二关:", r.text[:60])

# 第三关：带 cookie
r = requests.get(base + "/gate/3", cookies={"role": "admin"})
print("第三关:", r.text[:60])

# 第四关：路径穿越
r = requests.get(base + "/download", params={"file": "../flag.txt"})
print("第四关:", r.text[:60])

四段 flag 全出来，你就有了一件比 Burp 快得多的武器 —— 而且它是可复制的，改个地址就能打下一台。

PHP：为什么 Web 安全绕不开它

PHP 是"服务器端脚本语言"，跟第 Python 一样，代码在服务器上执行，用户只拿到结果。 它语法松、上手快、当年建站成本极低，所以国内早期的网站、CMS、论坛， 十有八九是 PHP 写的。

这些站后来大量还在跑，代码里塞满了老式写法 —— 这既是 Web 题的主要来源， 也是"一个 == 能翻出一堆绕过"的原因。

代码标记：一段 HTML 里怎么插 PHP

<?php echo "标准写法"; ?>      ← 最常用

<?= $a ?>                      ← 短输出，等价于 <?php echo $a; ?>

<? echo "短标记"; ?>            ← 需要 php.ini 里 short_open_tag=On

<script language="php"> ... </script>   ← 古老写法，早就不支持了
这个跟绕过有什么关系

有的站会把用户输入里的 <?php 过滤掉。但如果你能控制写入文件的内容， 用 <?= 短标签就能绕开这个过滤 —— 它同样是可执行的 PHP 代码。 这类"同一件事有多种写法"的差异，在文件上传、命令执行、模板注入里到处都有。

语句、注释、变量

<?php
// 单行注释
#  也是单行注释
/* 多行注释 */

$a = 1;          // 变量必须以 $ 开头，不需要声明类型
$name = "solo";
echo $a;         // 输出
unset($a);       // 删除变量
?>

三个细节：

  • 每条语句以 ; 结尾。但 ?> 自带结束效果，最后一行可以不带分号。
  • 变量名区分大小写，函数名不区分。
  • 命名规则和 C 一样：字母或下划线开头，后面可以跟数字。

预定义变量：题目的入口都在这儿

这九个全局数组，是 PHP 接收外部数据的窗口。你在做题时看到的每一个 $_GET['a']， 都是一个用户能控制的值。

变量装的是什么攻击面
$_GETURL 上的查询参数最高频
$_POST请求体里的表单数据高频
$_REQUESTGET + POST + COOKIE 三合一容易误取
$_COOKIE浏览器带来的 cookie可伪造
$_FILES上传的文件信息文件上传题
$_SERVER服务器与请求信息（含 Host、UA、IP）可伪造
$_SESSION服务端会话取决于逻辑
$_ENV环境变量配置泄露
$GLOBALS所有全局变量变量覆盖

记住一句话：这九个数组里的东西，全部来自客户端，全部可以伪造。 后端只要拿它们当"可信数据"用，就出问题。

可变变量：$$ 这个东西

如果一个变量的值正好是另一个变量的名字，可以用两个 $ 去取它： 

<?php
$a = 'b';      // $a 里存的是字符串 "b"
$b = 2;        // $b 的值是 2

echo $$a;      // 等价于 echo $b;  →  输出 2
?>

看着像个语言特性，实际上它是变量覆盖漏洞的底层机制之一。 想象 $a 是你从 $_GET 拿到的值，而代码后面又用 $$a 做了操作 —— 你传什么名字，它就操作哪个变量。

值传递和引用传递

<?php
$a = 1;
$b = $a;      // 值传递：各存各的，改谁不影响谁
$b = 2;
echo $a;      // 还是 1

$c = 1;
$d = &$c;     // 引用：加个 &，两个名字指向同一块内存
$d = 2;
echo $c;      // 变成 2 了
?>

& 是 PHP 的引用符号。它跟 C 的指针不是一回事， 但"改一个另一个也变"的效果是一样的。

作用域：函数里拿不到外面的变量

这一点和很多语言都不一样，初学者极容易懵： 

<?php
$x = 5;           // 全局

function test() {
    echo $x;      // 拿不到！这里是空的，会报 undefined
}
test();

function test2() {
    global $x;    // 必须用 global 声明
    echo $x;      // 现在能拿到了
}
?>

PHP 的函数作用域是封闭的。要在函数里用全局变量，得写 global $x;， 或者用 $GLOBALS['x'] —— 后者是超全局数组，在哪都能访问。

这个坑在审代码时很要命

你看到函数里用了 $flag，以为它是全局那个 flag，其实不是 —— 函数里那个是新的空变量。很多"明明赋值了却没生效"的逻辑漏洞就是这么来的。

常量

<?php
define("GREETING", "Welcome to JNWA!");
echo GREETING;          // 常量名前不加 $，也用不了 $
?>

常量定义后不能改，整个脚本里都能用。名字默认区分大小写。

数据类型

String、Integer、Float、Boolean、Array、Object、NULL。 表面上和别的语言差不多，但 PHP 是弱类型的 —— 这是下一节的全部素材。

PHP 弱类型：一个 == 能翻出多少事

这一节是 PHP 部分最值钱的地方。国内 Web 题里，"绕过一个比较"的套路， 八成都能在下面找到原型。

== 和 === 的区别

  • == 松散比较：只比值，不类型。类型不同它会先转换再比。
  • === 严格比较：值和类型都得一样。
<?php
var_dump(42 == "42");     // true   42 和字符串 "42" 转成同一类型后相等
var_dump(42 === "42");    // false  一个是整型一个是字符串
?>

看着正常。问题在于 PHP 转换的规则很野：

<?php
var_dump(12 == "12");      // true   显然
var_dump(12 == "12aa");    // true   字符串开头有数字，就取开头那段
var_dump("admin" == 0);    // true   转不成数字的字符串，变成 0
var_dump(0 == NULL);       // true
var_dump(true == "随便什么"); // true  布尔 true 和任意非空字符串弱相等
?>
这就是经典的"魔术哈希"

第三条 "admin" == 0 为真的原因是：比较数字和字符串时， 字符串如果转不成数字就变成 0，于是 0 == 0。

所以那种"密码不能等于 admin"的代码， if ($_GET['pwd'] == 'admin') die(); 后面如果还比 == 0， 就有得玩了。

0e 魔术：md5 弱比较的看家本领

0e 开头、后面全是数字的字符串，在弱比较里会被当成科学计数法： 0e123 就是 0 乘以 10 的 123 次方，结果还是 0。所以： 

"0e830400451993494058024219903391" == "0e462097431906509019562988736854"
// 两边都是 0 × 10^xxx = 0，判等成立

而正好有一批字符串，它们的 MD5 值就是这种形状：

原字符串它的 md5
QNKCDZO0e830400451993494058024219903391
2406107080e462097431906509019562988736854
s878926199a0e545993274517709034328855841020
s155964671a0e342768416822451524974117254469
s214587387a0e848240448830537924465865611904

所以这种题目：

<?php
include "flag.php";
highlight_file(__FILE__);
if (isset($_GET['a']) && isset($_GET['b'])) {
    $a = $_GET['a'];
    $b = $_GET['b'];
    if (($a !== $b) && (md5($a) == md5($b))) {   // 注意这里是 ==
        echo $flag;
    }
}
?>

两个值必须不一样（!==），但 md5 之后要弱相等。 直接传 ?a=QNKCDZO&b=240610708 就过了。

数组绕过：当 md5 收到一个数组

如果题目把 == 换成了 === 呢？0e 就不管用了。 但还有一条路： 

?a[]=1&b[]=2

这样 $_GET['a'] 拿到的是一个数组。而 md5() 只接受字符串， 传数组进去会报错并返回 NULL。于是： 

md5($a) === md5($b)   →   NULL === NULL   →   true

严格比较反而被绕过了。这个套路几乎所有"传参给函数比较"的地方都适用 —— 只要那个函数对数组会返回 null 或者报错。

还有一个：科学计数法绕长度

<?php
$a = $_GET['a'];
if (strlen($a) < 4) {
    if (($a + 1) > 1000) {
        echo "success";
    }
}
?>

长度小于 4，加 1 之后要大于 1000。正常数字做不到（999+1=1000 不满足大于）。 但传 ?a=1e3：长度 3，1e3 + 1 = 1001，过了。

PHP 危险函数：每一行都可能是个洞

PHP 内置上千个函数，其中有一批是 Web 题的常客。这一节挑六个讲， 每一个都能单独出一类题。

include：把一个文件塞进来

<?php
// 1.php
include "flag.php";       // 把 flag.php 的内容插到这儿执行
if ($_GET['a'] == $_GET['b']) {
    echo $flag;           // $flag 来自被 include 的文件
}
?>

include 会在执行时把指定文件的内容读进来、当作 PHP 代码执行。 这里的两个问题，是后面文件包含题的原型：

  • 如果 include 的路径来自用户输入 → 本地/远程文件包含（LFI / RFI）
  • 被 include 的文件里定义的变量，会在当前作用域里生效 → 变量注入

同族的还有 require、include_once、require_once，区别只在"找不到文件时的行为"和"是否重复包含"。

system：直接执行系统命令

<?php
system("dir D:");        // Windows 下列目录
system("whoami");        // Linux 下看当前用户
?>

这就是命令执行。一旦参数来自用户输入，服务器就是你的了。

同一家族还有几个，都得认识：

函数区别
system()执行并直接输出结果
exec()执行，输出最后一行，结果可以存进数组
shell_exec()执行，返回全部输出作为字符串
passthru()执行并原样输出二进制数据
反引号 `cmd`等价于 shell_exec()，最容易被忽略
反引号那个坑，很多题就靠它

有人装了 disable_functions，把 system、exec、 shell_exec 全禁了，却忘了反引号走的也是 shell_exec。 于是 echo `whoami`; 照样能执行。

这类"禁了 A 忘了 B"的清单式防护，永远有漏网的。

eval：把字符串当代码跑

<?php
eval('echo "hello";');     // 字符串里的内容会被当作 PHP 代码执行
?>

eval 比命令执行更危险 —— 它执行的是 PHP 代码， 不是系统命令。区别在于：

  • 代码执行 —— 跑的是 PHP，能读变量、能调函数、能 include
  • 命令执行 —— 跑的是系统命令，受限于当前用户的权限

从代码执行到命令执行，通常只要再 system() 一下。

extract：变量覆盖的老祖宗

<?php
$a = "Original";
$arr = array("a" => "Cat", "b" => "Dog");
extract($arr);
echo $a;      // 输出 Cat —— 原来的值被覆盖了
?>

extract() 把数组里的键值对，变成当前作用域的变量。 如果这个数组是 $_GET，那就是用户能覆盖任意变量： 

<?php
highlight_file(__FILE__);
include "flag.php";
extract($_GET);                    // ← 危险在这里

foreach ($_GET as $var) {
    if (preg_match("/[a-zA-Z0-9]/", $var)) {   // 只是检查了值，没检查键
        die("error");
    }
}
if ($cmd) {
    echo $flag;
}
?>

检查的是值里不能有字母数字，但变量名（键）没管。 所以传 ?cmd=1 就能让 if ($cmd) 成立。

同族的还有几个

parse_str()、import_request_variables()（老版本）、 以及 $$key = $value 这种手写循环，效果都差不多：把用户输入变成变量。

register_globals 那个上古开关早就默认关了，但手写的"变量覆盖"至今还在。

md5：不可逆，但可以被绕过

md5() 把任意长度输入压成 32 位十六进制，是单向的，解不回去。 但在 PHP 题里，出问题的从来不是"解密"，而是拿它去比较。

三种常见玩法，上一节已经讲过两种：

  • 0e 绕过 —— 弱比较时两个 0e... 都当 0
  • 数组绕过 —— 传数组进去返回 null，null === null
  • 真碰撞 —— 找到两个不同字符串 md5 完全相同（这对连字符都要求一样，网上有现成的一对）

最后那种，题面通常要求 md5($a) === md5($b) 且 $a !== $b， 而且限制了必须是字符串。那就只能拿现成的碰撞对了。

这一节说完，你应该有个感觉

PHP 的坑不是"语法没学懂"，而是每个函数的边界条件，都可能被人利用。 弱类型的转换规则、函数对异常输入的行为（返回 null？报错？截断？）、 变量作用域的怪癖——这些"边角料"，才是出题人待的地方。

Java：为什么安全的人躲不掉

如果你只打算做点小型 CTF Web 题，Java 可以先放一放。 但只要往深了走 —— 大厂面试、大型比赛、真实的业务系统 —— Java 这道坎绕不过去。 原因很实在：企业里跑的 Web 系统，大头是 Java 写的。

而 Java 安全里最难的那块（反序列化、RMI、JNDI）， 全都建立在这一节要讲的东西上：类、对象、接口、注解、反射。 基础不牢，那些题你看一眼就会觉得"每一个字都认识，连起来不是人话"。

它怎么运行：先编译，再解释

源代码 .java  --(javac 编译)-->  字节码 .class  --(JVM 执行)-->  运行结果

这是 Java 的"一次编写，到处运行"：编译出来的不是机器码，是字节码， 由各个平台上的 JVM 负责执行。所以同一个 .class 在 Windows、Linux、macOS 上都能跑。

最早的 Java 是纯解释执行，后来加了 JIT 即时编译（把热点代码编译成本地机器码）， 所以现在它算是一种"混合型"语言。

第一个程序

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}

文件必须叫 HelloWorld.java —— 文件名和 public 类名必须一致， 这是硬规定，不像别的语言随便起。

数据类型：基本类型 + 引用类型

Java 有八种基本类型，和 C/C++ 基本一样：

byte、short、int、long、 float、double、char、boolean

除此之外全是引用类型：类、接口、数组、枚举、注解。 这两者的区别，后面反序列化会反复用到：

  • 基本类型直接存值，放在栈上
  • 引用类型变量里存的是对象的地址，对象本身在堆上
int[] a = {1, 2, 3};

这一行创建了一个数组对象（在堆上）， a 这个变量在栈上，存的是这个对象的地址。 所以 Java 的数组本质也是对象，有 length 属性。

两个常见的坑
  • 下标越界抛 ArrayIndexOutOfBoundsException，不像 C 那样静默越界
  • 数组长度定死，不能动态扩容。要变长得用 ArrayList

String 不能用 == 比

String name = "solowalker";
if (name.equals("solo")) {
    System.out.println("walker");
}

== 在 Java 里比的是"两个引用是不是指向同一个对象"， 而 equals() 比的才是内容。字符串内容比较必须用 equals。

这一点在安全里正好是漏洞

有的业务代码用 == 比字符串（比如权限、口令）， 在特定情况下会因为字符串池的复用而"碰巧相等"或"应该相等却不相等"， 导致校验被绕过。这类问题在代码审计里是实打实的点。

条件和循环

int score = 85;
if (score >= 90) {
    System.out.println("优秀");
} else if (score >= 60) {
    System.out.println("及格");
} else {
    System.out.println("不及格");
}

// switch 的箭头写法是 JDK 17 才有的，老版本和 C 一样
int day = 3;
switch (day) {
    case 1, 2, 3, 4, 5 -> System.out.println("工作日");
    case 6, 7 -> System.out.println("周末");
    default -> System.out.println("非法输入");
}

// 增强 for：遍历数组和集合，比下标舒服
int[] arr = {1, 2, 3};
for (int n : arr) {
    System.out.println(n);
}

方法：重载 vs 重写

这两个词长得像，含义完全不同，面试必问：

重载（Overload）重写（Override）
在哪同一个类里子类覆盖父类的方法
什么变方法名相同，参数列表不同方法名、参数、返回值都相同
何时决定编译期（静态绑定）运行期（动态绑定）
 
// 重载：同一个 add，三种参数
public int add(int a, int b) { return a + b; }
public int add(int a, int b, int c) { return a + b + c; }
public double add(double a, double b) { return a + b; }

// 重写：子类改写父类的方法
class Animal {
    public void speak() { System.out.println("动物叫声"); }
}
class Dog extends Animal {
    @Override
    public void speak() { System.out.println("汪汪"); }
}

重写是后面反序列化链子的关键。 因为父类引用指向子类对象时，调用的到底是哪个 speak()， 是运行期才决定的 —— 攻击者可以伪造一个"看起来是父类、实际是子类"的对象， 让你的调用跑到他想跑的实现上去。

类和对象：OOP 的四个词

类是一个"抽象概念"，对象是它的"具体实例"。 拿苹果打比方：你嘴里说的"苹果"是个概念，手上拿着的那一个才是对象。

为什么要这么组织代码？先看面向过程怎么写：

# 数据和函数是分开的
student_name = "张三"
student_age = 18

def print_student(name, age):
    print(f"{name}, {age}岁")

代码少的时候没问题。上千行以后，你根本记不住"哪个函数在动哪些数据"。 面向对象把数据和行为打包在一起： 

class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def birthday(self):
        self.age += 1

    def introduce(self):
        print(f"我是{self.name}，{self.age}岁")

zhangsan = Student("张三", 18)
zhangsan.birthday()
zhangsan.introduce()

四个核心概念，逐个说人话：

  1. 封装 —— 把内部细节藏起来，只暴露必要的方法。 外面不知道对象里有什么，只知道能调什么。
  2. 继承 —— 子类自动拥有父类的属性和方法。 苹果是一种水果，苹果类就可以继承水果类，水分、甜度这些属性不用重写。
  3. 多态 —— 同一个调用，在���同对象上有不同表现。 行话叫"父类引用指向子类对象"。
  4. 抽象 —— 只关心"做什么"，不关心"怎么做"。 接口里只声明方法，具体实现交给实现类。
多说一句：注解为什么重要

注解（@Override、@RestController 这些）本质是贴在代码上的标签， 自己不改变逻辑，但能在运行时被"反射"读出来，然后决定要做什么。

Spring 那一套全靠这个：看到一个 @RequestMapping 就知道这个方法对应哪个 URL。 而反射 + 注解 + 反序列化，正好是 Java 安全问题里最热闹的那一桌。

异常和注解，知道有这么回事就行

try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("除数不能为 0：" + e.getMessage());
} finally {
    System.out.println("无论如何都会执行");
}

try-catch-finally 用来兜住运行时错误，别让整个程序崩掉。 注解的写法长这样（自定义一个）： 

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)      ← 关键：运行时还能读得到
@Documented
public @interface Log {
    String value() default "";
    int level() default 1;
}

注意 @Retention(RUNTIME) 那一行 —— 它决定了这个注解是"编译完就丢"， 还是"运行时还在，能被反射读出来"。后面那一类，才是攻击者关心的。

Java 这块别指望看一遍就懂

OOP 那四个概念，靠读是读不明白的。敲代码，自己写几个类继承一下、重写一下、 用接口实现一下，手感才会出来。

讲台上推荐的是 狂神说 Java， 跟着敲一遍基础部分就够用了。
